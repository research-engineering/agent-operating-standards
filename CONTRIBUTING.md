# Contributing

Contributions should improve a reusable operating standard or the repository
surface that maintains those standards.

## Issues

Use issues for proposals, contradictions, missing standards, unclear ownership,
or template defects. A useful issue states the affected surface, the expected
invariant, the observed gap, and the impact.

## Pull Requests

Pull requests should be small and owner-scoped. A pull request should include:

- the problem being solved;
- the affected standard or governance surface;
- the invariant preserved by the change;
- validation or review performed;
- explicit non-claims.

Use squash merge for accepted pull requests. Merge commits and rebase merges are
not part of this repository's normal history model. Do not add workflow
requirements or release-style gates before the repository admits a workflow
evidence standard.
